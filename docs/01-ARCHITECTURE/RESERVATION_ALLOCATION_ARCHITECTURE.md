# معمارية الحجز والتخصيص — Reservation & Allocation Architecture

**الحالة:** قيد المراجعة — تقتصر على قرارات الأعمال المؤكدة فقط
**المرجع:** `docs/01-ARCHITECTURE/BUSINESS_SPECIFICATION_RESERVATION_ALLOCATION.md` (مواصفة الأعمال الرسمية)
**التسليمية التالية (مؤجلة):** وثيقة تصميم مخطط قواعد البيانات وعقود الـ RPC (Schema and RPC Contracts Design)
**تاريخ الخط الأساسي:** 2026-08-01 — بيانات طلبات الإنتاج = صفر (بعد Task 0)

> **قاعدة حوكمة:** هذه الوثيقة لا تتضمن أي سلوك مقترح أو افتراض أو خيار تصميم غير مؤكد. كل ما ليس قرار أعمال مؤكداً **مؤجَّل** إلى القسم 5 (للمرحلة التالية) ولا يُعتبر جزءاً من الأساس المعتمد.

---

## 1. الغرض والنطاق

توثّق هذه الوثيقة الأثر المعماري الذي تفرضه قرارات الأعمال المؤكدة الخاصة بمحرك حجز وتخصيص المخزون، وتفصل بوضوح بين:

- ما هو **ملزِم بقرارات الأعمال المؤكدة** (أساس معتمد)، و
- ما هو **مؤجَّل** إلى مرحلة تصميم مخطط قواعد البيانات وعقود الـ RPC (وليس جزءاً من الأساس).

المرجع الوحيد لقواعد الأعمال هو المواصفة الرسمية.

---

## 2. قرارات الأعمال المؤكدة والأثر المعماري المباشر

> **لقراء الأعمال:** شرح كل قاعدة بلغة أعمال مبسطة (Business Meaning) تجده في المواصفة الرسمية — `BUSINESS_SPECIFICATION_RESERVATION_ALLOCATION.md` (القسم 2).

| القاعدة | الأثر المعماري المباشر (ملزم بالقاعدة) |
|---------|----------------------------------------|
| BR-RS-01 | كل تعديل على الطلب يزامن الحجز تلقائياً ليعكس أحدث نسخة — بغض النظر عن الحالة السابقة |
| BR-RS-02 | نقصان الكمية → نقصان الحجز بنفس المقدار فوراً |
| BR-RS-03 | زيادة الكمية → زيادة الحجز فوراً عند توفر سعة؛ عند محدودية السعة تُطبَّق نفس قواعد الحجز |
| BR-RS-04 | الخروج من حالة الحجز → تحرير الحجز تلقائياً وفوراً |
| BR-RS-05 | الحجز على مستوى المنتج الفردي داخل الطلب؛ إزالة منتج تحرّر حجزه فقط دون بقية المنتجات |
| BR-RS-06 | إدارة الحجز تلقائية بالكامل؛ لا حجوزات قديمة؛ لا صيانة يدوية |
| BR-RS-07 | لا انتهاء صلاحية زمني؛ التحرير بأحداث الطلب فقط |
| BR-RS-08 | كل تعديل — مهما كانت الحالة (بما فيها `approved`) — يزامن المخزون والحجز مع أحدث نسخة |
| BR-AL-01 | عند محدودية السعة: الأول في التقديم يُحجز أولاً، والحجز الجزئي حتى سعة المتاح |
| BR-SU-01 | عمليات الحجز والتخصيص بوحدات بيع كاملة فقط |
| BR-SU-02 | تغيير `carton_quantity` يسري تلقائياً على الطلبات القديمة والجديدة |
| BR-VIS-01 | المندوب: إرشاد + حد أقصى بوحدة البيع فقط — لا أرقام مخزون/حجز/مستودع |
| BR-VIS-02 | الإدارة: رؤية تفصيلية للمخزون والحجز وفق الصلاحيات |
| BR-AUD-01 | سجل أحداث الطلب يوثق كل عملية حجز/تخصيص/تعديل/خصم/استرجاع/تحرير (timestamp, actor, reason, previous, new) |

## 3. الأساس الفعلي الحالي (حقائق مرجعية فقط)

نظام خصم المخزون الحالي لا يتضمن أي نموذج حجز:

- `inventory`: سجل واحد لكل منتج، `quantity` (بالقطع).
- `products.negative_selling_allowed` (افتراضي `true`)، `products.inventory_deduction_status` (افتراضي `approved`)، `products.oos_source`.
- لقطات على مستوى الطلب: `orders.order_negative_selling_allowed`, `orders.order_inventory_deduction_status`, `orders.inventory_deducted_at`, `orders.inventory_deducted_items`.
- `inventory_movements`: سجل حركات الخصم والاسترجاع.
- RPCs قائمة: `governed_inventory_deduct`, `governed_inventory_restore`, `governed_check_product_availability`, `governed_change_order_status`.

---

## 4. التبعية المعروفة (تُعالج في مرحلة التصميم القادمة)

> **التبعية:** بموجب BR-RS-08، تعديل طلب سبق خصمه (`inventory_deducted_at` غير فارغ) يستلزم مزامنة المخزون مع أحدث نسخة من الطلب. تُسجَّل هنا **كتَبَعية معروفة فقط** — دون حل أو تصميم — وتُعالج في وثيقة Schema & RPC Contracts Design.

---

## 5. عناصر مؤجَّلة لمرحلة التصميم (ليست قرارات أعمال مؤكدة)

كل ما يلي **خيار تصميم، سلوك مقترح، أو افتراض لم تؤكده إدارة الأعمال** — مؤجَّل إلى وثيقة Schema & RPC Contracts Design، ولا يُعتبر جزءاً من الأساس المعتمد:

1. نموذج تخزين الحجوزات (مادي/مشتق) وجداوله وأعمدته وفهارسه.
2. الحساب الدقيق لسعة الحجز (الرصيد، حجوزات الطلبات الأخرى، حجز الطلب نفسه) وتفاعله مع سياسة البيع بالسالب.
3. مجموعة حالات الحجز الدقيقة (أي الحالة تُفعّل الحجز / تُبقيه / تحرّره) بما فيها معاملة `draft` و`deferred` و`stock_review`.
4. مفتاح أولوية "الأول في التقديم" وسياسة إعادة التخصيص بين الطلبات ونطاقها وأداؤها.
5. عقود الـ RPC الجديدة (إعادة الحساب، إرشاد المندوب، تفاصيل الإدارة) ونقاط ربطها في المسارات المدارة.
6. بنية سجل أحداث الطلب وأنواع الأحداث.
7. تحديث RPCs القائمة: `governed_change_order_status`, `governed_inventory_deduct`, `governed_check_product_availability`.
8. سلوك النفاد التلقائي (`oos_source = 'inventory'`) مع الحجوزات.
9. معاملة العروض اليومية/الوميضية في حساب كميات الحجز.
10. آليات المتزامنة والذرية (المعاملات، الأقفال، إعادة التنفيذ).
